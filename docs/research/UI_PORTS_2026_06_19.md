## AI-Elements — PATTERNS-ONLY (native wins)
`vercel/ai-elements` Apache-2.0; a shadcn-registry of ~20 React chat components tied to React+Tailwind+AI-SDK `useChat` — **structurally incompatible with the WebKit-host vehicle** (not a self-contained Lit/Vite bundle). Epistemos already has native equivalents for the whole catalog (MessageBubble, AssistantInlineTranscriptView, InlineThinkingTranscriptSegment, ToolExecutionPreviewCard, ArtifactBlockView, MessageToolbar, EidosRetrievedSection, LiveActivityStrip…). WEBKIT-MAX explicitly carves this out ("does NOT loosen native-first where native genuinely wins", ledger:1189). Mine its taxonomy → the 2 real native gaps: **no syntax highlighting in chat code blocks** (TaggedMarkdownTextView:641 plain mono, while tree-sitter highlighter exists for the editor) + **no math/KaTeX in chat** (EpdocKaTeXPreview is editor-only). Effort: Low. (R-ELEMENTS has NO verdict doc — this is it.)

## Streamdown — PATTERNS-ONLY native (+ optional tiny WebKit)
`vercel/streamdown` Apache-2.0, react-markdown drop-in; value = graceful incomplete/unterminated-block streaming + Shiki/KaTeX/Mermaid/rehype-harden. Epistemos chat is 100% native (`TaggedMarkdownTextView` hand-parser + `AttributedString`), re-parses full md per token (`ChatView:555`, 48-LRU) — already does the headline (live md while streaming) but via full re-parse, no highlight/math. Recommend NATIVE primary: (a) unterminated-block tolerance in the parser, (b) wire the existing tree-sitter highlighter into chat code, (c) reuse `EpdocKaTeXPreview` WebView for `$$`. WebKit only genuinely wins for **Mermaid** (no native analog) — small sandboxed WKWebView like KaTeX. Don't port the React renderer. Effort: low–med. Overlaps R-HTMLSTREAM (same DOMPurify/rehype-harden core — share one sanitizer) + R-ELEMENTS.

## HTML canvas (P7.2) — already-covered + targeted fixes (NOT broken-from-scratch)
The surface S5 called "broken" is substantially built+wired: `HTMLWorkspacePackage` (manifest+index/style/script+**dataJSON**+sandbox), `HTMLWorkspaceDocument`, **`HTMLWorkspacePatchRouter`** parses ```` ```epistemos-html-workspace-patch ```` → 9 typed ops w/ content-hash guard + `<script>`/handler stripping + `contextPack` injects the live workspace into the prompt (= the Claude-Artifacts "agent edits the live doc" loop, on native infra), `HTMLWorkspaceEditorView` (panes + consolePanel + per-pane MiniChat), `HTMLWorkspacePreviewView` (WKWebView), ~13 call sites. **Real fixes:** (1) code panes have NO syntax highlighting (`HTMLWorkspaceCodeEditor` plain NSTextView — the "can't see code" suspect; reuse tree-sitter); (2) preview uses `loadHTMLString(baseURL:nil)` not the proven `epistemos-doc:` scheme handler (relative-asset/CSP inconsistency); (3) `safeAPI` message handler is an empty stub (no two-way drive); (4) no live patch→WKWebView push (no-reload). Already WebKit (correct — a canvas must be). Classification = debug+harden+connect (this IS S16 R-LIVE-ARTIFACTS' surface). MAS core (local) / Pro (live feeds). Effort: medium-LOW.

## Terminal (P7.3) — PORT (UI only)
Backend is a real hardened Rust engine: `terminal.rs` `terminal` (sh -lc, timeout+output-cap, fg/bg sessions) + `process` (list/poll/log/kill/write) via `harden_cli_subprocess`; `#[cfg(pro-build)]` + `enable_bash` false off-pro + triple MAS barrier (compile-out + name-deny + Destructive-deny, test-locked). **No Swift terminal UI** anywhere. Missing piece = a terminal emulator → **xterm.js (MIT) bundled via the build-tiptap pattern → WKWebView fed by the Rust terminal/process stream over WKScriptMessageHandler; keystrokes → process write** = the clearest WEBKIT-MAX win (mature, ANSI/resize/scrollback, upstream-trackable, pixel-skinnable). Native alt = SwiftTerm (MIT) but more binding work. Pro/dev only (keep the triple barrier; MAS shows disabled "Pro · Developer build only"). Plan: `build-terminal-bundle.sh` + `TerminalHostView` (copy EpdocEditorChromeView trio incl dismantle + shared processPool) + `epistemos-terminal:` scheme + FFI stream bridge + **home it in WORK** (wire the inert `work.rs`/`WorkBackend.swift`, currently EngineNotWired). Effort: medium (backend done). Overlaps R-GOOSE/Work (prereq) + the 3-engine toggle (S6 — sequence after that primitive).

## Cross-cutting
- 3 of 5 are NOT ports: AI-Elements + json-render = patterns-only; HTML canvas = already-built+fix. Only terminal (UI) + Streamdown/StreamHtml (optional) are real WebKit ports.
- **R-ELEMENTS + Streamdown owe a verdict doc** (WEBKIT-MAX policy requires one per port) — this slice is the substance; add ledger verdict entries.
- **Build ONCE, reuse:** (a) a shared "progressive-render" primitive serves Streamdown(chat)+SpecStream(GenUI)+R-LIVE-ARTIFACTS(data.json); (b) a shared WebKit-host kit (custom-URL-scheme handler + pixel-skin CSS injector [S2] + tree-sitter syntax highlighter) underpins HTML-canvas + terminal + OpenClaw + StreamHtml + KaTeX. Building the scheme handler, the skin injector, and the highlighter ONCE is how **S2 (reskin) + S14 (ports) + S16 (live-artifacts) compose instead of collide.**
- The tree-sitter syntax highlighter is the single highest-leverage shared fix: it closes the chat-code-highlight gap (R-ELEMENTS), the HTMLWorkspace code-pane "can't see code" gap (P7.2), and Streamdown's highlight gap — one wire, three surfaces.
