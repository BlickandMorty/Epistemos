## ★ TOP FINDINGS
1. **Cmd+K is FREE** [VERIFIED-CODE] — `grep 'keyboardShortcut("k"'` returns nothing. App-level shortcuts (12 of them) live in ONE place: `struct EpistemosCommands: Commands` (`EpistemosApp.swift:1446`, attached `:974`); `@main` at `:934`.
2. **No registry/palette/EditorCommand type exists today** — entirely new subsystem (grep matched only `editor.commands` JS substrings).
3. **~80% of Epdoc commands are already dispatchable** through existing `EpdocEditorCommand.runCommand(name:argsJSON:)` (generic JS fallback `inbound.ts:340`) + `.insertSlashChoice(blockType:)` — the registry mostly WRAPS what's wired. Real ADDs are small (below).
4. **The `isEnabled` honesty gap:** `caretChanged` carries only rect+selection today (no marks) — so mark-active state is only correct right after a command runs, not when the caret moves into existing bold. Fix = add a `marks:{}` payload to `caretChanged` (3 files).
5. **Shortcut conflicts flagged:** ⌘1/2/3 (Home/Notes/Goose, app-level) → headings/panels must be focus-scoped; ⌘E double-booked (inline-code vs mark-organized → inline-code moves to ⌘⇧E); ⌘K (was link → now palette → link moves to ⌘⇧K); ⌘⇧I (Image vs Properties → Properties wins); ⌘G (app-level → code findNext needs focus-scope).

### Pass 10a — Unified CommandRegistry + Cmd+K palette core

**`CommandRegistry` core (NEW `Epistemos/Engine/CommandRegistry.swift`)** — `@Observable` (NOT ObservableObject, CLAUDE.md), `@MainActor`. A `Command` value type: `id` (stable string), `title`, `subtitle`, `symbol` (SF Symbol), `shortcut: KeyboardShortcut?` (declared ONCE here → menu + palette both read it), `scope` (`.global`/`.note`/`.code`), `menuPath` (`.file`/`.edit`/`.view`/`.format`/`.workspace`/`.none`), `isEnabled: @MainActor () -> Bool`, `run: @MainActor () -> Void`. API: `register(_:)` with **dedup-by-id** (re-register REPLACES → idempotent under hot-reload, never doubles a menu entry), `matching(query:scope:)` = scope-narrowed (`.global ∪ activeScope`) + `isEnabled`-filtered + subsequence-fuzzy-scored (prefix/word-boundary bonuses, strongest hit floats to top — the palette never lists an unrunnable command = `validateMenuItem` parity), `menuCommands(path:)` for the menu bar. A single `var activeScope` (`@Observable`) set by whichever editor is key narrows palette + scoped menus.

**Cmd+K palette (NEW `Epistemos/Views/Command/CommandPaletteView.swift`)** — native SwiftUI (NOT webview): auto-focused search field, filtered `List` off `registry.matching`, `.onKeyPress(.downArrow/.upArrow/.escape)` nav, Enter-to-run (deferred via `Task { @MainActor in cmd.run() }` so the sheet tears down before a command that itself presents a window). `.regularMaterial` rounded card, 620pt wide. Each row shows title/subtitle/SF-symbol + the `Command.shortcut` label. Wired as a `.sheet($showCommandPalette)` with a new `CommandGroup(after: .toolbar){ Button("Command Palette"){…}.keyboardShortcut("k", .command) }` in `EpistemosCommands` (Cmd+K verified free).

**One registry → three surfaces:** (a) **menu bar** — a `RegistryMenu(path:)` view renders `menuCommands(path)` inside the existing `CommandGroup`/`CommandMenu` anchors (`EpistemosApp.swift:1451–1539`), each `Button` taking `.keyboardShortcut(cmd.shortcut)` + `.disabled(!cmd.isEnabled())` (literal `validateMenuItem`); the hand-rolled buttons collapse into `Command` definitions. (b) **shortcuts declared once** on `Command.shortcut` — the prior 12 hand-typed `.keyboardShortcut(...)` calls become registrations in a new `CommandRegistrations.swift` (each preserving current behavior 1:1, e.g. `app.knowledgeGraph`→`KnowledgeGraphShortcutDispatcher.toggle()` ⌘G `:1493`, `app.goose` with `isEnabled:{ GooseSurfaceAvailability.current().isReady }` `:1478`). (c) **palette** reads the same `commands` array — a toolbar command is Cmd+K-discoverable with zero extra code. **`isEnabled` drives all three** (menu `.disabled`, palette `matching` filter, active-state checkmark).

**Scope model:** `.global` always visible; `.note`/`.code` visible only when that surface is key. `activeScope` set in each editor's coordinator on key/resign (`EpdocEditorChromeView.Coordinator` → `.note`; `CodeEditorView` → `.code`; reset `.global`). [INFERRED] `FocusedValue` is not used in any scene today — wire via the coordinator's existing key-window knowledge; if SwiftUI menu-shortcut precedence proves ambiguous for ⌘1/2/3, fall back to ⇧⌘1/2/3.

### Pass 10b — Command catalog + dispatch wiring

**Verified seams:** `EpdocEditorCommand` enum (`EpdocEditorBridge.swift:564–617`: `setContent`/`focusStart`/`focusEnd`/`dismissSlashMenu`/`insertSlashChoice(blockType:)`/`dismissBubbleMenu`/`runCommand(name:argsJSON:)`; `javaScriptExpression()` `:593`; `jsStringLiteral` escaper `:623`). Canonical dispatch = `EpdocEditorChromeController.dispatch` (`EpdocEditorChromeView.swift:124`) → `evaluateJavaScript`. Toolbar model active-mark flags (`EpdocEditorToolbar.swift:54–59` + `activeHeadingLevel:53`). JS: `window.epistemos.*` named handlers + generic `runEditorCommand` fallback (`inbound.ts:340` = `editor.chain().focus()[name](...).run()`); slash block IDs (`slash-menu.ts:83–123`). Code editor: no command enum today, two ad-hoc JS calls (`setState:175`, `selectRange:186`); find/goto/outline logic exists as `@State`+functions (`CodeEditorView.swift:2790/2200/1835`).

**Note catalog (curated to Pass-1a keep-list).** Dispatchable via existing cases: bold/italic/strike/highlight/inline-code (R `toggle*` via fallback), codeBlock (`toggleCodeBlock`), headings (`setHeadingLevel [{level}]`), paragraph (`setParagraph`), lists/quote/divider/table/math/callouts (S `insertSlashChoice`), link (`setLink`), image (`insertEpdocImage`), frontmatter (`insertEpdocFrontmatter`). Controller closures (not bridge cases): save (`onSave :128`), HTML-workspace, Properties/ToC/AI-panel toggles (native `@State`). **Must ADD:** `EpdocEditorCommand.setContentWidth(wide:)` (CSS var `--epdoc-content-max-width` exists `editor.css:80` but zero Swift setter — sets `'none'` vs `'760px'`); Epdoc `find` (no ProseMirror search wired); `markOrganized`/`favorite` as host closures (SDPage `_organized`/`_favorite`, ontology 4a `SystemKeys`).

**Code catalog (planned `CodeEditorCommand` enum — entirely ADD, NATIVE_CONTROLS §49):** find/findNext/findPrevious/goToLine/outline/livePreview/lspHover all have EXISTING logic to wrap; `replaceRange`/`setWrap`/`toggleComment`/`fold`/`unfold` need NEW `window.epistemosCodeEditor.*` JS methods (today only `setState`/`selectRange`) — OR land natively with the CM6/CoreEditor swap (codepack 4b). **Define the enum against the bridge contract, not the engine**, so it survives the swap.

**Dispatch glue:** registry `run` closures call `chrome.dispatch(.runCommand(name:argsJSON:))` / `.insertSlashChoice(blockType:)` reusing the existing `jsStringLiteral` escaper + `commandArgsJSON` (no new escaping). Code commands go through existing `@State`/functions or a `replaceRange` `evaluateJavaScript` mirroring `selectRange`. **Echo safety:** note mutations ride the intended `contentDidChange`→`EpdocEditorSavePipeline` 300ms debounce (not a loop; only `setContent` suppresses via `emitUpdate:false`), so no re-entrancy guard needed; code find/goto are read+selection-only (echo-safe), only `replaceRange` writes text and must round-trip the existing `change`→debouncer path.

**Enabled-state (`isEnabled` = `validateMenuItem`):** note sources already on `chrome.toolbarModel` (`isBoldActive…isHighlightActive :54-59`, `activeHeadingLevel`, `isDirty :47`). **THE GAP:** `caretChanged` carries no marks (`bridge.swift:476`, emit `index.ts:150`, `EpdocBridgeSelection:396` has no marks) → add `marks:{bold,italic,strike,code,highlight,heading}` to the JS emit + extend `CaretChangedMessage` (`outbound.ts:54`) + the Swift decode → set the toolbar flags on caret move. Also ADD `toolbarModel.editorIsFocused` (focus/blur bridge msg or derive from `selection != nil`); bold/italic enabled only when focused (ideally non-empty selection). Code editor enabled-state is fully derivable from existing `@State` (`!text.isEmpty`, `!searchQuery.isEmpty && activeSearchRange != nil`, `totalLines > 0`, LSP `canRun(language:)`) — no read-back needed.

**Build order (from the pack):** registry core → Cmd+K palette → register existing app commands (1:1 behavior preservation) → note catalog over existing cases → `caretChanged.marks` read-back + `editorIsFocused` (honest `isEnabled`) → ADD `setContentWidth` + Epdoc Find → `CodeEditorCommand` enum (find/goto wrap now; replace/wrap/fold/comment with the CM6 swap). The whole thing is foundational: it makes the menu bar, every shortcut, and the palette one coherent source, and gives the later Find/width/panel/code work a single place to land.
