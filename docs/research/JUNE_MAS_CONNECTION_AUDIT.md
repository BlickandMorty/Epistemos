## Executive Verdict

Primary verdict after Phase B source forge: HALF-WIRED, improving toward CONNECTED.

The prior prime suspect was real: before this cycle, June's cloud turns were still direct chat and local rows claimed function-calling to satisfy the picker. That is now fixed in source. June cloud turns route through the in-process `GooseMASAgentCoreRunner`, stream text/thinking/tool/approval/completion events into the June runtime, and use the active app vault path when `VaultSyncService` is already watching a selected security-scoped vault.

The honest remaining blocker is proof, not plumbing: DoD-2 still requires a running sandboxed App Store build task that reads and writes the user's vault through the approval UI. The code now has the source path for that proof, but the proof has not been captured in this cycle. Runtime probing did capture one useful truth-boundary result: unconfigured cloud access now fails loudly with a Settings-directed `cloudNotConfigured` message instead of pretending to work.

During this continuation pass, the hardening review found and fixed one source-level HIGH in the MAS runner: the new `agent_core` event stream had been created without an explicit buffering policy. It now uses `.bufferingNewest(256)`, and `AppStoreJuneHardeningTests` has a source guard to keep it that way.

The same memory lens found the local June token wrappers were also using default unbounded streams. `JuneAgentGateway`, `AppleFMQuickChatBackend`, `LocalGGUFQuickChatBackend`, and the retained `JuneCloudEngine` scaffold now use `.bufferingNewest(256)`. This continuation deliberately avoided native builds/tests while an unrelated Experimental `xcodebuild` and Swift frontends were active on the 16 GB machine.

The new Prompt Forge mandate is now source-wired for the MAS June composer. A pre-submit `prompt.forge_preview` RPC returns an on-device deterministic upgrade, bounded active-vault citations, an honest no-citation path, and a selected-model context strategy; the June composer shows Original/Upgrade review with change summary, context budget, citations, and Accept/Edit/Retry/Revert before `prompt.submit`. The implementation now lives in `JunePromptForge.swift` instead of expanding `JuneAgentGateway.swift`; `JuneSessionStore.swift` and `JuneGatewayTypes.swift` carry storage/shared types. Later feature wiring brought `JuneAgentGateway.swift` back above the 1k-line risk line; hardening passes extracted vault scope, tool-event bounding, model row building, conversation context assembly, and approval tracking into `JuneAgentCoreVaultScope.swift`, `JuneToolEventBounds.swift`, `JuneAgentModelCatalog.swift`, `JuneAgentConversationContext.swift`, and `JuneAgentApprovalRegistry.swift`. Replay value types now live in `JuneGatewayTypes.swift`. The gateway is down to 990 lines, below the maintainability threshold. Runtime proof remains open.

The System Prompt Forge companion is now source/web-wired as a deterministic MAS-safe settings feature. `JuneSystemPromptForge.swift` provides an original pattern library, visible preview payloads, active-vault grounding by reusing the existing Prompt Forge citation path, atomic Application Support persistence for accepted behavior, and runtime composition into both cloud and local gateway instructions. The local runtime layer explicitly overrides custom behavior so local rows remain chat-tier, compact-context, and tool-free.

User-added context/thinking requirements are now partially landed in source: local models are treated as compact-context engines in the catalog, Prompt Forge profile, history envelope, and GGUF reply budget; cloud models expose reasoning/thinking capability flags from `CloudTextModelID.supportedOperatingModes` and `supportsNativeReasoningEffortControl`; the generic Cloud Agent row derives its thinking label from the currently configured OpenAI/Anthropic model and otherwise stays tool-capable-without-thinking-label until Settings is configured; local text streams split real inline think tags into `thinking.delta` without advertising fake local tools. The latest continuation fixes three source gaps: lower-context local rows now compute history/reply budgets from the selected model window, OpenAI/Codex picker rows no longer collapse to legacy `gpt-4o` aliases before reaching `agent_core`, and DeepSeek Reasoner no longer collapses to the generic non-thinking `deepseek-chat` constructor. `gpt-5.x` / Codex slugs route to matching native Responses constructors with reasoning summaries, Kimi K2.7 Code uses the documented `thinking` parameter, DeepSeek Reasoner routes to a distinct `deepseek_reasoner` slug, and Z.AI/GLM routes request native `thinking` plus `reasoning_effort` while still staying non-agent-tier in June. Swift capability truth now marks GLM rows with Rust Z.AI thinking/effort extensions as provider-native effort-controllable and labels heavy Z.AI effort as `Max`; Kimi keeps Rust-level native thinking on/off support without fabricating a low/medium/high UI effort ladder. The remaining thinking frontier is runtime proof across configured Codex/OpenAI/Claude/Gemini/Zai/Kimi/DeepSeek rows and any 1Code/opencode-specific models, which this MAS June lane does not own.

The finalization mandate adds a cloud-first default. Source now reflects that: `currentDefaultModelID()` prefers a configured cloud provider model and otherwise selects the generic `JuneModelID.cloud` lane so the first send fails honestly with `cloudNotConfigured` rather than silently downgrading to local chat. Local remains the secondary privacy/offline lane.
