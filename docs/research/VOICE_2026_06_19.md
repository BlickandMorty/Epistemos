## ROUND-2 DEEPENING — "plain voice" root cause + high-def path (2026-06-19)

**The owner is right, and here's the exact mechanism.** `preferredVoice()` ALREADY prefers premium>enhanced>default (`EpistemosSpeechSynthesizer.swift:219-228`), so why still plain? Three reasons:
1. **Premium/Enhanced ("Siri-quality") neural voices aren't installed** — Apple ships only Compact by default; Enhanced/Premium are a manual download (Settings → Accessibility → Spoken Content → Manage Voices) "most users never discover." The code's `voiceQualityHint():235` lives only in the per-model picker, NOT where the owner hears the plain voice.
2. **The fallback floor is the plainest voice** — when no en-premium/enhanced exists, the final fallback `AVSpeechSynthesisVoice(language:):227` returns COMPACT. No "best installed voice regardless of language" tier first.
3. **No prosody/SSML** — every utterance is a bare `AVSpeechUtterance(string:):140` (rate+pitch only); `AVSpeechUtterance(ssmlRepresentation:)`/attributedString unused → even a good voice reads flat/monotone.

**⚠️ CRITICAL macOS-26 REGRESSION (web-confirmed, likely the owner's exact symptom):** on iOS/macOS 26, `AVSpeechSynthesisVoice(language:)` **ignores the user-selected premium/3rd-party voice and silently returns the system default** (Apple Forums 804648, FB20271264). Epistemos's fallback floor at `:227` uses the LANGUAGE constructor → so on macOS 26 the app lands on the plain voice **even when a premium voice is installed AND selected.** Documented workaround: **address voices by `identifier`, NEVER by language.**

**The fixes (all MAS-safe, pure AVSpeech, no subprocess/download):**
- **A. best-installed floor** — after en-premium/enhanced misses, pick the highest-`quality` voice across ALL installed voices before the language fallback (never Compact if any Enhanced exists).
- **B. dodge the regression** — resolve/persist by IDENTIFIER only; the floor must NOT use `AVSpeechSynthesisVoice(language:)`.
- **C. surface the install hint where it's heard** — promote `voiceQualityHint()` to a dismissible banner near read-aloud + onboarding ("your Mac is using the basic voice — install a Premium voice [Open Manage Voices]"); deep-link exists (`ModelVoicePickerSection.swift:195`).
- **D. prosody via SSML** — add an `AVSpeechUtterance(ssmlRepresentation:)`/attributedString path (failable → keep plain fallback); lifts even Compact off monotone.

**The "new Siri voice" — web-validated:** the **neural Siri voice is NOT exposed to 3rd-party apps** via AVSpeech. What IS newly available (macOS/iOS 26.4) is the **upgraded Personal Voice** (near-instant creation on M1+/A17 Pro): call `AVSpeechSynthesizer.requestPersonalVoiceAuthorization()` and Personal Voices appear in `AVSpeechSynthesisVoice` alongside system voices — the closest legitimate "Siri-quality custom voice" through the public API. Plan 3 now wraps this auth call in `EpistemosSpeechSynthesizer` and exposes it in the shared voice picker.

**Ranked installable upgrades (Pro, blocked by the model-download bug):** **#1 Kokoro-82M** — Apache-2.0, beats Apple Enhanced (~Premium), **turnkey zero-Python Swift CoreML/ANE** (`mweinbach/kokoro-swift`, `mattmireles/kokoro-coreml` — 379ms/30s, 2× MLX), 1-2GB; host it via `FluidInference/FluidAudio` or `Blaizzy/mlx-audio` (don't hand-roll). **#2 Piper** (MIT, ONNX, weaker, no Swift turnkey). **License-BLOCKED:** F5-TTS (CC-BY-NC), XTTS/Coqui (CPML non-commercial). **No Apple-Silicon Swift path yet (later):** Sesame CSM-1b (Apache, best quality), Dia-1.6B (Apache), MOSS-TTSD (ONNX). **Ship rec: Kokoro-82M is the only model that's better-than-Apple AND Apache-2.0 AND has a real on-device Swift path AND fits RAM.**
