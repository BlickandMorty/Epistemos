# Architecture Tier Promotion Canon - 2026-06-06

North-star sentence: Epistemos is a local cognitive substrate where every
meaningful object has an address, plane, budget, status, and witness; MAS
ships the safe floor, Pro contains the gated/research/vault/omega ladder, and
no claim promotes without visible proof.

This canon defines how Epistemos moves from ambitious architecture to actual
user-facing product truth. It supersedes vague "done", "green", "working",
"compiled", or "live" language. A mechanism becomes green only when it is
wired, reachable, visible, verified, compiled into the correct build, and
truthfully described to the user.

The end goal is the full architecture operating as one typed local substrate:
intent becomes a mission packet; every meaningful object resolves to UAS/OAS;
ColdStore/AppColdStore proposes addressable candidates; ActiveAssembly wakes
the smallest sufficient support set; Eidos validates evidence and route priors;
SCOPE-Rex/SovereignGate admits or denies the route; RuntimeRouter/System G
executes; post-validation repairs or rejects; and RunEventLog plus AnswerPacket
make the result visible, replayable, and reversible.

## Tier Ladder

These tiers are promotion bands. They do not replace L1/L2/L3; they make those
truth layers harder to misread.

| Tier | Name | What exists | What cannot be claimed |
|---|---|---|---|
| T0 | Canon / Research / Vault | Source research, ambition, architecture language, candidate organ, donor motif, or preserved future work. | No runtime, no product capability, no user-facing completion, no green. |
| T1 | L1 Architecture Proof | Typed primitive, source guard, metadata falsifier, artifact, deterministic address, budget/status/witness, no duplicate cursor risk. | No L2 product route unless capability kernel says so. Metadata-only PASS is not product truth. |
| T2 | L2 Capability Route | Actual route contract is wired through admission, RuntimeRouter/System G, rollback, RunEventLog, AnswerPacket, capability kernel, and focused tests. | No broad user-facing green until WRV proves real surfaces. |
| T3 | L3 WRV Surface | The feature is Wired, Reachable, Visible, and Verified in product surfaces with log-correlated evidence. | No release/ship green until compiled build and release audit pass. |
| T4 | Build-Green Capability | Correct MAS or Pro build compiles, tests pass for the declared scope, copy/onboarding/settings are honest, runtime is gated as declared, rollback works, and release-audit evidence is zero-fail for that claim. | No full architecture completion unless all required organs and rows for the segment reach T4 or are explicitly red/blocked. |
| T5 | Full Substrate Segment | A named architecture segment is end-to-end: identity, state, assembly, controller, verification, user surface, rollback, and witness all operate together under MAS/Pro truth. | No app-wide completion unless every segment has a T4/T5 status or an explicit blocked/red list. |

## Color Semantics

Use color/status words only with the tier.

| Status | Allowed meaning |
|---|---|
| Red | Known blocker, failed test, missing runtime proof, capability kernel false, unsupported build path, or deliberate research-only state. |
| Amber | Gated, partial, scaffold-only, or Pro Research with a clear next falsifier. |
| Blue | L1 source/metadata proof exists and the architecture cursor advanced, but product/user truth did not. |
| Green | T4 or higher only: compiled/reachable/user-facing or build-scoped capability with tests/logs/witnesses and honest MAS/Pro copy. |

Never use "green" for T0, T1, or metadata-only evidence.

## Full Architecture End-State

The full Epistemos architecture is not "all metadata falsifiers pass." The full
end-state is this:

1. MAS ships the safe floor with no hidden Pro/Omega promises.
2. Pro exposes gated, research, vault, and omega ladders honestly.
3. Every user-facing capability has a real route from app surface to substrate
   organs and back to visible proof.
4. Every local model, provider, retrieval, mutation, and tool route is admitted,
   reversible, logged, and answer-visible.
5. Every architecture segment has a tier row: green T4/T5, amber gated, or red
   blocked with the missing falsifier/test/runtime proof named.
6. Large-model ambition remains alive as cold assembly, routing, residency,
   transport, compression, and harness work without live dense-70B overclaims.
7. Autogenous/Omega work remains Pro Research until crash-safe harness,
   dry-run witnesses, rollback, and owner-approved probes exist.
8. The Living Index, lattice HTML, Master Research Index, prompts, falsifier
   handbook, and regenerated artifacts tell the same story.

## Green Checklist

A claim can become green only if all applicable checks pass:

- Source exists and is reachable from the product bootstrap, agent loop,
  RuntimeRouter/System G, or declared surface.
- Admission is explicit: SCOPE-Rex/SovereignGate verdict, policy, and denied
  actions are visible where relevant.
- Route is explicit: selected lane, fallback/abstention, model/provider/tool,
  memory preflight, timeout, cancellation, and rollback.
- Verification is real: focused tests, falsifier, validator, logs, manual step,
  or release audit evidence matches the claim.
- User surface is real: not a hidden health row, not doc-only, not a disabled
  mode pretending to succeed.
- AnswerPacket and RunEventLog expose route, evidence, caveats, and rollback or
  a visible failure packet.
- MAS/Pro copy is honest and unsupported modes are hidden or explicitly gated.
- Build scope is declared: MAS, Pro Live, Pro Gated, Pro Research,
  VaultPreserved, or Omega.
- `git diff --check`, relevant focused tests, relevant falsifier validator,
  capability kernel, architecture guard, and doctrine lint have run or have an
  explicit reason for deferral.

## What Does Not Promote

These never promote a claim by themselves:

- A doc row without artifact evidence.
- A metadata-only PASS.
- A stale artifact whose `commit_sha` does not match the reported state without
  an explicit drift note.
- A model card, repo README, fork, benchmark blog, or copied code snippet.
- A hidden route, hidden provider, hidden PatternBoost policy, or hidden
  lattice/oracle decision.
- A local runtime sidecar that is not product-reachable or user-visible.
- A passing product source guard when the capability kernel remains red.
- An in-app UI label with no log-correlated runtime or manual verification.
- A heavy-runtime proof that bypasses owner approval, crash safety, memory
  preflight, cancellation, rollback, and visible packet evidence.
