# Constructive Residency Paradigm - 2026-06-01

## Thesis

The new paradigm is not "fit a 70B dense model in hot RAM." The paradigm is:

> **Construct the smallest proof-carrying resident assembly that can solve the task.**

Epistemos should treat a large local brain as a cold, addressable construction
space. For each task, the system searches for a bounded assembly of model
pages, experts, KV pages, adapters, evidence, verifier lanes, controller state,
and tool plans. That assembly gets a route card, a memory budget, a verifier,
and a rollback handle before it runs.

This makes the 70B cocktail more plausible without pretending physics changed.
UAS makes cold bytes nameable. AppColdStore makes them layout-controlled.
ActiveAssembly makes the working set small. Eidos and verifiers make the route
honest. The cold atlas is not RAM. It is a construction field.

## L11-Candidate: Constructive Residency Law

Local capability scales with the quality of the selected resident assembly, not
with the largest parameter count simultaneously hot.

```text
Utility(assembly | task, state) =
  verifier_delta
  + evidence_delta
  + reasoning_continuity_delta
  - hot_bytes_cost
  - kv_bytes_cost
  - wake_latency_cost
  - cold_miss_penalty
  - interference_risk
  - rollback_risk
```

Promotion condition:

- the assembly beats dense-local, RAG-only, and static-routing baselines;
- the route reports total addressable bytes, hot resident bytes, active
  executed bytes, KV bytes, adapter bytes, cold bytes, peak RSS, and cold
  misses;
- all cold wakes are scheduled or explicitly skipped;
- the answer includes citations/verifier results where required; and
- `RunEventLog` and `AnswerPacket` expose the route, failure modes, and
  rollback.

## New primitive set

### `ResidencyConstructionGraph`

Graph of candidate assemblies and their constraints.

```text
ResidencyConstructionGraph {
  task_signature
  candidate_units
  coactivation_edges
  incompatibility_edges
  verifier_edges
  cold_miss_history
  assembly_score
}
```

### `CoactivationTile`

A layout unit for bytes that tend to be useful together.

```text
CoactivationTile {
  tile_id
  model_or_memory_id
  units: weight_page | expert | kv_page | adapter_slice | evidence_bundle
  byte_ranges
  codec
  expected_reuse_horizon
  prefetch_cost
  verifier_history
  rollback_ref
}
```

### `ColdAssemblyPlan`

The admitted execution patch.

```text
ColdAssemblyPlan {
  mission_id
  active_tiles
  warm_tiles
  cold_tiles
  hot_bytes
  warm_bytes
  cold_bytes
  kv_bytes
  peak_rss_estimate
  prefetch_order
  verifier_stack
  fallback_route
  rollback
}
```

### `LatticeStateController`

Always-hot controller that reasons over route states, not over all knowledge.

```text
LatticeStateController {
  task_signature
  abstract_state_lattice
  admissible_actions
  abstain_condition
  verifier_feedback
  next_route_action
}
```

### `ProofCarryingResidencyLease`

A short-lived permission to wake cold bytes.

```text
ProofCarryingResidencyLease {
  unit_id
  uas_address
  lease_reason
  active_byte_cost
  expected_utility
  proof_or_falsifier_ref
  expires_at
  rollback
}
```

### `ReasoningStateContinuityCard`

Continuity policy for useful state across turns.

```text
ReasoningStateContinuityCard {
  session_id
  model_id
  preserved_state_kind: kv_summary | prompt_cache | reasoning_summary | tool_state
  privacy_class
  visible_summary
  cache_key
  restore_policy
  verifier_caveat
  purge_policy
}
```

Never expose hidden chain-of-thought as product truth. Preserve state to improve
continuity and cache utility, then verify claims separately.

### `ColdMissLedger`

Planning failure memory.

```text
ColdMissLedger {
  route_id
  missed_unit
  miss_time
  stall_ms
  fallback_used
  verifier_delta
  next_prefetch_policy
}
```

## How this makes the 70B cocktail more plausible

The 70B cocktail becomes a set of routed roles, not one monolithic resident
blob:

| Role | Hot/warm/cold posture |
|---|---|
| always-hot controller | small local model, SSM/hybrid controller, or recurrent lattice controller |
| verifier lanes | Lean/schema/test/citation workers woken by task need |
| evidence substrate | Eidos-selected notes, citations, graph islands, and source cards |
| large model pages | cold AppColdStore pages or MoE expert tiles, prefetched by route |
| adapters | small specialist deltas selected by task and verified repair history |
| KV/reasoning state | paged, compressed, resumable, privacy-scoped continuity artifacts |
| rollback/witness | AnswerPacket, RunEventLog, route card, lease, and falsifier artifact |

The system wins if the hot controller plus selected support behaves better than
the hot controller alone, and if every extra byte earns its rent.

## Engineering route

1. **Source intake.** Store Axplorer, SwiftLM, Letta, PowerInfer, vLLM, LMCache,
   Qwen, and LDT as `SourceCard`s with license/status notes.
2. **Dry-run construction.** Build `ResidencyConstructionGraph` over synthetic
   pages and current route-card metadata.
3. **Tile layout.** Pack `CoactivationTile` manifests in AppColdStore without
   changing live model execution.
4. **Lease simulation.** Emit `ProofCarryingResidencyLease` and `ColdMissLedger`
   in a dry-run route.
5. **Cache-lineage dry run.** Add `KVPrefixUnit`, `KVCompatibilityFence`, and
   `CacheAdmissionCard` fixtures before persistent KV/prefix reuse.
6. **KV continuity.** Add `ReasoningStateContinuityCard` for cache summaries,
   not hidden chain-of-thought product claims.
7. **SwiftLM source mining.** Study SwiftLM's SSD streaming and KV compression
   for motifs only; no code import without license/setup/vendor gates and tests.
8. **Verifier tournament.** Compare candidate assemblies against dense-local,
   RAG-only, and static-route baselines.

## Hard no-overclaim rules

- Do not say SSD is equivalent to RAM. Say addressable, schedulable,
  prewarmable, mmap-able where measured, and cold until promoted.
- Do not claim 70B dense local comfort until a falsifier reports quality,
  memory, latency, and visibility pass.
- Do not treat X bookmarks as authority. They seed research; primary repos,
  papers, and local falsifiers govern promotion.
- Do not import public code into product paths without license/setup/vendor
  review, tests, and rollback.
- Do not expose or persist hidden chain-of-thought as user-facing proof.
- Do not let a feature atlas, route prior, or preserved reasoning state bypass
  Eidos, SCOPE-Rex/SovereignGate, RunEventLog, and AnswerPacket.
