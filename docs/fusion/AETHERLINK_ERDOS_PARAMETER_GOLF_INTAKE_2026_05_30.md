# AetherLink Erdos / Parameter Golf Intake - 2026-05-30

## 0. Verdict

The useful lesson is not "copy the Erdos proof" and not "make the app sound
like a math contest."

The useful lesson is:

```text
hard problem
  -> choose a higher-dimensional coordinate chart
  -> search constructions there
  -> project back to the target surface
  -> keep a witness coordinate
  -> let humans/verifiers judge the result
```

For Epistemos and AetherLink, this becomes the **Coordinate Construction
Engine**:

```text
ProblemCard
  -> LiftChart
  -> ConstructionGraph
  -> ProjectionPacket
  -> Witness / Falsifier
  -> AnswerPacket
  -> promote | fork | quarantine
```

This is the grand, unique expression: Epistemos is not "an AI model that gives
answers." It is a proof-carrying coordinate runtime that searches better charts
for memory, model residency, control, and research construction, then projects
only witnessed results back to the user.

## 1. Public Research Check

### 1.1 Erdos unit-distance result

Primary source:

- OpenAI, "An OpenAI model has disproved a central conjecture in discrete
  geometry," 2026-05-20:
  https://openai.com/index/model-disproves-discrete-geometry-conjecture/

Grounded facts from the source:

- The problem is the planar unit-distance problem posed by Paul Erdos in 1946.
- OpenAI reports that an internal model disproved the longstanding conjecture
  that the best lower bound was essentially `n^(1+o(1))`.
- The article says the proof was checked by external mathematicians.
- The construction uses ideas from algebraic number theory, including
  number-field methods.
- The article states that Will Sawin later made the exponent explicit.

Companion source:

- Will Sawin, "An explicit lower bound for the unit distance problem,"
  arXiv:2605.20579, submitted 2026-05-20:
  https://arxiv.org/abs/2605.20579

Grounded facts from the arXiv abstract:

- Sawin shows arbitrarily large planar point sets with more than
  `n^1.014` unit-distance pairs.
- The method relies on algebraic number fields with large degree and small
  discriminant plus a Golod-Shafarevich criterion argument.

Architecture intake:

```text
Erdos motif = lift to a richer coordinate chart, search there, project back,
and preserve a witness.
```

Do not claim:

- Epistemos has solved a comparable open problem.
- Lift/project is automatically optimal for every domain.
- A generated construction is verified without a local proof or falsifier.

### 1.3 Parameter Golf ecosystem

Primary sources:

- OpenAI Parameter Golf repository:
  https://github.com/openai/parameter-golf
- OpenAI, "What Parameter Golf taught us," 2026-05-12:
  https://openai.com/index/what-parameter-golf-taught-us/

Grounded facts from the sources:

- Parameter Golf asked participants to minimize held-out loss on FineWeb under
  a 16 MB artifact limit and a 10-minute 8xH100 training budget.
- OpenAI reports more than 1,000 participants and more than 2,000 submissions.
- The official repository had roughly 5.1k stars and 3.4k forks at intake.
- The repo includes an Apple Silicon MLX local training path.
- OpenAI highlighted quantization, test-time/evaluation strategies,
  tokenizer/data-representation ideas, and efficient attention variants as
  notable submission families.

Architecture intake:

```text
Parameter Golf motif = every useful byte must justify itself under a public,
reproducible score.
```

For Epistemos, this becomes:

```text
WeightBlockManifest
  + ResidencyPlan
  + WBO budget
  + dense/reference rollback
  + local falsifier
  + size/latency/copy-count score
```

This is more directly reusable than the Erdos repos because it is a live
compression/search competition with reproducible code, public records, PRs,
and MLX support.

## 2. The Unified Motif

Erdos and Parameter Golf are duals.

| Erdos result | Parameter Golf | Epistemos/AetherLink primitive |
|---|---|---|
| `n` points | 16 MB artifact budget | UAS address/residency budget |
| maximize unit-distance pairs | minimize validation bits-per-byte/loss | WBO/error ledger |
| higher-dimensional number-field chart | compression, tying, quantization, recurrence, TTT | lift chart / IR chart |
| projection back to the plane | executable model artifact | ProjectionPacket |
| proof checked by experts | PR/log/reproducibility review | verifier/falsifier/AnswerPacket |
| surprising construction | size-efficient model behavior | Research Construction Engine |

The system-level invariant:

```text
Lift what is expensive or opaque into a richer coordinate chart.
Search there under an explicit budget.
Project back into a small executable surface.
Carry the witness and the rollback path.
```

## 3. What This Means For The 70B / ColdStore / UAS Ambition

The user's core target remains:

```text
Use SSD as ColdStore, UMA as hot active assembly, UAS/AcsAnchor for address and
provenance, and SCOPE-Rex/SovereignGate as the admission governor so a 16 GB
```

Erdos gives the chart doctrine. Parameter Golf gives the scoring discipline.

The immediate build primitive should not be another crash-prone full model
probe. It should be a construction card and residency planner:

```text

  file_uri
  candidate_weight_blocks
  candidate_kv_pages
  candidate_adapter_deltas
  lift_chart: nf4 | ternary | sherry | leech | eml | geometry | scan | opaque

  cold_mmap_budget_bytes

  falsifier: F-70B-Local-Cocktail | F-KV-Direct-Gate | F-Sparse-Runtime-Split
```

If a proposed active set does not fit the memory/copy/WBO budget on paper, it
does not get to touch the model runtime. That is how we keep the laptop alive
while still moving toward the no-compromise target.
