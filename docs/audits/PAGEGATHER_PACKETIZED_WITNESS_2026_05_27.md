## Why This Exists

The dense scheduled kernel preserves caller-visible order by writing:

```text
out[logicalPositions[i]] = source[indices[i]]
```

That contract is correct but slow on M2 Pro because the destination writes are
random. The packetized scheduled kernel keeps the same witness coordinate while
avoiding immediate dense restore:

```text
packetValues[i] = source[indices[i]]
packetLogicalPositions[i] = logicalPositions[i]
```

This matches the Substrate Motion Invariant: recall may move as compact packets
with explicit coordinates, and dense projection is paid only when a consumer
actually needs dense logical order.

packet stream clears the `0.70x` M2 Pro floor at the 256/512 MB envelope named

  `restore_packets` only when needed.

  restore still needs optimization before promotion.
