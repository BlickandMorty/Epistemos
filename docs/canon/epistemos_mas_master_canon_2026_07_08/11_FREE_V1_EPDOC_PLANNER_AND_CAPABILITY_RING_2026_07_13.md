  planning truth.
- Approved audio, transcript, PDF, dataset, and export files remain referenced
  artifacts.
- Approved drawings, images, and other rich media remain portable referenced
  artifacts; Markdown stores stable human-readable references, never opaque
  media/database blobs.
- Stable IDs must survive rename/move and may be added only through a readable,
  round-trippable Markdown convention proven against existing Epdoc content.
- RECKONER workbook/dataset formats remain artifact truth for tabular data.

Rebuildable projections:

- Inbox, Today, This Evening, Upcoming, Anytime, Someday, Logbook, calendar
  agenda, task search, and task counts are indexes over vault truth.
- Calendar events and reminders remain EventKit truth. Epistemos stores stable
  references and user-authored links/context; it does not silently duplicate
  the user's whole calendar into a private authoritative database.
- Search, graph, GRDB, caches, thumbnails, embeddings, and planner indexes are
  derived and disposable.

Shared seams:

- Writes flow through KEELSTONE coordinated/atomic write paths.
- Epdoc/LUMENLENS owns visible Markdown editing and minimal-diff writeback.
- One provenance schema records task moves, completion, rescheduling, meeting
  links, time-block/calendar publication, capture promotion, and exports.
- One event bus publishes note/task/meeting/calendar/sync/dataset changes.
- No task room, planner database, meeting database, transcript database, sync
  authority, or parallel reconciler may be added.

## Native rich-object and cross-lens contract

The typed object manifest is a derived document index, not new durable truth.
It must identify each supported or unknown embedded/reference object, its stable
ID, type, Markdown source range or reference token, artifact path relative to
the authorized vault, availability, permission state, accessible label, and
the lens actions that are safe. Rebuild and incremental parsing must agree.

Object families admitted to the program are tasks/checklists/projects,
calendar and reminder links, meeting references, audio/voice notes,
transcripts, drawings, images, general attachments, PDFs, and RECKONER dataset
or chart references. Admission is per family: schema/round-trip, sandbox and
permission behavior, accessibility, performance, export portability, crash
recovery, and App Review evidence must pass before Epdoc presents the family as
complete.

The inspector is not a fallback database or a hidden editor. It reports the
same manifest in every lens. Selecting an item navigates to the Markdown source
or opens the Epdoc representation without replacing the owner toolbar, title
ontology, KEELSTONE write path, or MarkEdit Source grammar.

The PDF lens consumes the same manifest. For an Epdoc note, its PDF is a derived
rendition generated from Markdown and portable artifacts with an explicit
Epistemos print/export style using the approved palette, registered fonts,
hierarchy, and images. Any live rendition is debounced, cancellable, cached,
and off the typing/scroll path. Structural body edits route back to Epdoc or
Source and regenerate while retaining the page/source anchor.

Imported PDFs remain their own user-owned artifact truth. The lens may edit
public PDFKit annotations, form fields, and explicitly proven page operations,
but must not claim arbitrary imported body-text reflow/editing. Epistemos
palette/font defaults apply to app chrome and newly created annotations, not by
silently recoloring or replacing original page content. Save a Copy is the
default mutation route until atomic in-place security-scoped conflict evidence
passes.

## Meeting integration

Meeting is a workspace capability, not a separate room.

- A meeting note can link to an EventKit event identifier, calendar title,
  time range, attendee references, agenda, decisions, sources, follow-up tasks,
  and referenced audio/transcript artifacts.
- Meeting creation starts from an Epdoc template or a user-selected calendar
  event and writes through KEELSTONE.
- Follow-up tasks are ordinary vault tasks and appear in the same Today,
  Upcoming, project, search, and graph projections.
- Recording requires explicit consent, a persistent visible recording state,
  bounded retention, and crash-safe artifact finalization.
- Voice-note recording and dictation are distinct owner actions. A voice note
  may exist and play without a transcript; transcription must retain source-
  audio linkage and an honest local/system-service availability state.
- Free V1 dictation uses only explicit owner-invoked macOS system dictation or
  text input. It must not bundle or start an Epistemos-owned speech-recognition
  model, automatically/background-transcribe audio, enable June/provider/
  sidecar work, or create a separate transcript database. If exact artifact or
  runtime evidence cannot preserve that literal boundary, integrated
  transcription stays disabled and ordinary system text-input dictation is the
  only admitted path.
- Kokoro may read selected Epdoc or meeting text aloud locally. Microphone
  consent is not requested for read-aloud alone.

## Native MAS integration supremacy audit

Epistemos should exceed ordinary note and planner apps through coherent native
integration, not feature-count theater. Before implementing this ring, build a
current source-backed matrix from official Apple documentation and public
vendor material for successful Mac productivity, notes, planning, document,
and journal apps. Record what is documented, what is inferred, which public API
could support an Epistemos version, the entitlement/privacy/App Review cost,
the data-authority seam, and the measurable performance risk. Learn public
capability patterns only; never copy proprietary code, formats, trade dress,
icons, screenshots, or branded interaction details.

Candidate families to research and admit independently are:

- App Intents, App Shortcuts, Shortcuts/Siri discovery, Spotlight indexing and
  searchable-item deep links. Modern generated App Intents metadata is the
  active contract. Legacy `INIntentsSupported` is allowed only if the app truly
  handles the named `INIntent` subclasses directly; a stale declaration is not
  an integration.
- macOS Services, share/open-in flows, document-type associations, drag and
  drop, copy/paste, Quick Look, Finder/document interoperability, and truthful
  deep-link/restoration routes into the same vault artifact.
- WidgetKit and notifications for owner-selected, privacy-bounded planner or
  capture state, with stale-data, relevance, deep-link, app-group, denial, and
  background-budget evidence.
- EventKit Calendar/Reminders, deterministic task/date parsing, explicit writes,
  least-privilege access, deletion/change handling, and no calendar clone.
- Explicit system dictation/text input, app-owned voice-note recording/playback,
  Kokoro read-aloud, media controls where appropriate, and strict separation
  from hidden transcription, June, providers, or another bundled model.
- Full keyboard navigation, VoiceOver, Voice Control, reduced motion, contrast,
  Dynamic Type or equivalent scalable text behavior, accessibility actions,
  labels, rotors/focus order where applicable, and accessible exported content.
- Native document/PDF/print/export/Quick Look behavior, file coordination,
  security-scoped bookmarks, open-in-place or safe-copy semantics, undo,
  autosave/conflict/recovery, and honest unsupported states.
- `NSUserActivity`, scene/window restoration, Handoff, continuity, and system
  search suggestions only where one stable Epistemos route and privacy-safe
  payload can be proven without duplicating document or navigation authority.

Grounded 2026-07-14 research found no single private “secret” MAS API. The
