### What “no AI” means for the retained Free product

- Forbidden: generative models, chat, agents, June, LumenLens AI, providers,
  autonomous workflows, assistant suggestions, semantic/model inference that
  starts implicitly, NaturalLanguage contextual embedding-model execution,

  metadata search, file indexing, graph traversal, rules, dates, native UI,

- Kokoro is the one explicit app-owned model exception for user-invoked
  read-aloud.
- User-invoked macOS speech transcription is retained as an input capability,
  but must be labeled and permission-gated honestly; it may not authorize a
  general inference state, provider, assistant, or background model route.
- Vision/OCR and semantic embeddings are not silently admitted by the words
  “native integration.” Each needs an explicit capability decision and current
  privacy/performance/runtime evidence. Until then, Free V1 must fail closed;
  lexical/metadata behavior remains available.

## P0 retain, harden, and prove register

### P0-G - One truthful editor architecture

Final architecture:

- Markdown `.md` has distinct Prose, Preview, and Source lenses over one file.
  They are not separate Markdown documents and Prose is not consolidated into
  Source.
- Epdoc is a standalone native TextKit 2 JSON `.epdoc` document with its own
  autosave, undo, recovery, graph identity, and explicit export/publish paths.
- Epdoc never synchronously mirrors into Markdown. Explicit `Export/Publish as
  Markdown` creates a normal `.md` note that then belongs to Markdown lenses.
- PDF is a derived Epdoc rendition or an imported user-owned PDF, never a
  second silent document authority.
- Legacy `content.pm.json`/ProseMirror Epdoc packages require a versioned,
  engine-neutral rich-block migration receipt before native TextKit 2 becomes
  the only write path. Migration must be backward-readable, stable-ID aware,
  repeatable, crash-safe, and must preserve unsupported bytes/assets visibly.

Open hardening:

- Confirm what the Epdoc Save button currently does. Keep it only if it is an
  honest explicit checkpoint/commit action distinct from live autosave;
  otherwise remove the stale duplication and make save state understandable.
- Prove atomic save, crash recovery, close/reopen, external change handling,
  undo/redo, conflict behavior, and export without cross-format overwrite.
- The old JSON ProseMirror mirror is not required merely to switch between
  Markdown lenses; remove any mirror/hot-path bloat not needed for compatible
  import/export after exact caller and fixture audits.
- Ordinary Save writes only the canonical JSON `.epdoc`. `Publish/Export
  Markdown Copy...` is a separate explicit action: collision-safe, never
  overwrites an existing `.md`, writes an independent ordinary Markdown note
  under an `Epdoc Exports/Markdown` destination or an owner-selected location,
  records additive origin metadata, reports lossy/unsupported blocks and copied
  assets, and creates no reverse sync. `Export PDF Snapshot...` is likewise an
  explicit snapshot action. Current source has explanatory copy but no proven
  Markdown publisher or PDF snapshot command.

### P0-H - Large-document performance and data-loss safety

The owner's 67k-word KEELSTONE document, a representative 67k-72k-word stress
fixture, and the retained 72k-character unit fixture are mandatory stress
inputs, not ordinary architecture documents to expand.
The owner directly observed hangs, lag, text restoration after backspace,
disappearing/reappearing content, scroll/edit jumps, surface-switch failures,
and save/toggle failures.

Required hardening:

  syntax rebuild, layout rebuild, or mirror write on each keystroke.
- Coalesce derived projection/checkpoint work, cancel superseded work, perform
  expensive work off the input turn, and preserve one ordered document
  transaction/undo authority.
- Use viewport/layout fragment behavior appropriate to TextKit 2 and MarkEdit;
  never hide unloaded text as a performance shortcut or replace dirty content
  with a stale projection.
- Audit observers, Combine tasks, timers, WKWebView handlers, caches, graph
  projection, search indexing, autosave, windows/tabs, Settings, and every
  editor host for leaks, duplicate work, unbounded retention, and main-thread
  stalls.

Required matrix on one exact current app:

- 4k, 20k, 67k-72k-word, and 72k-character Markdown/Epdoc fixtures, plus a
  two-times-large rich JSON envelope for projection/viewport stress;
- first open, repeated open, type, rapid backspace/delete, paste, select,

## Editor/product design details that must not be stranded

- Preserve Matrix regular, Matrix Bold, Matrix Dots/type variants, Chonky, and
  GNF/Greetings font resources and registration. Source H1 uses Matrix Bold;
  ordinary Source metrics remain MarkEdit-derived.
- Keep the Epistemos palette and shared native toolbar/title ontology while
  making Source presentation near-verbatim MarkEdit and Epdoc controls native
  macOS-quality. “Keep chrome” in prior discussion meant palette plus toolbar,
  not permission to keep every old low-quality surface element.
- Epdoc remains the default rich document, not a plain Markdown-looking clone
  of Source. Its JSON architecture was selected to eliminate synchronous
  cross-lens recalculation, not to remove rich presentation.
- Source, Prose, and code must expose a shared information/object inspector for
  embedded objects they cannot safely render inline. Selecting an entry must
  navigate to the exact source/object.
- Native controls should learn interaction motifs from Things, NotePlan,
  Diarly, MarkEdit, and robust open-source editors without copying their trade
  dress. Calendar/task/reminder/audio/drawing/image capabilities are product
  behaviors, not screenshot duplication.
- Tolaria remains AGPL behavior-study/provenance only and is not shipping code.
  Native TextKit 2 is the selected Epdoc foundation because viewport/layout,
  undo, accessibility, and App Store ownership must be proven in Epistemos.
- The MarkEdit preview/eye and title Name/Tags/Where popover are distinct:
  preserve both, with the shared Epistemos identity ontology.
- The Epdoc notebook/tab strip must not interleave stale Chat or parked Sheet
  launchers with the note body. Compatibility data can remain stored without a
  visible tab.
- Home mode and graph embedding must render the same document authority as the
  multitask host; they are destinations, not copies.
- Cross-format object inspection must respect the final split: Epdoc objects
  belong to `.epdoc`; Markdown inspectors describe only objects actually
  referenced by that `.md` or an explicit exported-origin relation. There is no
  ambient synchronous Epdoc-to-Markdown mirror or magical shared object store.
