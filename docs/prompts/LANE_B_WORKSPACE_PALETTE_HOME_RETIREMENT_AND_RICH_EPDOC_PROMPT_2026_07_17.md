## P0-A — Build Workspace Palette and completely retire Home

This is the primary Lane B outcome.

Create exactly one separate native macOS companion window named **Workspace
Palette**:

```text
WORKSPACE PALETTE
[ Now | Notes | Graph | Settings | Today | Organize ]

MULTITASK WORKSPACES
[ Note | Epdoc | Graph View | Editor | Research | … ]
```

The Palette:

- has one instance, one authoritative identity, and no competing fallback
  creator;
- launches compactly, remembers size/position/section, and is hide/show-able;
- is not always-on-top by default;
- defaults several deliberate notches wider than the current Notes Sidebar,
  remains far smaller than the former Home window, and is generously resizable
  to practical screen limits by user choice;
- preserves the real Notes Sidebar glass/material family: blur, layered depth,
  borders, texture, header/search chrome, hover behavior, and native Mac
  character;
- responds gracefully at compact and expanded widths, light/dark, increased
  contrast, reduced transparency, and Reduce Motion.

## P0-C — Epdoc as a durable notebook workspace

Build this on the rich JSON editor; do not substitute a display-only tab strip.

```text
[ Epdoc header + controls ]
[ Pinned Cards ]
[ Main Document or active child content ]
```

## P0-F — Calendar/Today, Organizer, tasks/reminders, and inline voice notes

P0-A owns the Palette placement; this section owns the durable behavior and
integration contract.

### Daily Epdoc and date ownership

- A date resolves to one stable daily-Epdoc identity in the selected vault.
  Creation is atomic/idempotent and inspectable; open/reopen, date navigation,
  time-zone/DST changes, rapid selection, and multiple windows never fork it.
- The daily Epdoc is an ordinary full rich canonical-JSON Epdoc that
  participates in hierarchy, links/backlinks, search, graph, export, history,
  and recovery. A template may seed content once but never becomes a second
  source of truth or overwrites user edits.
- The editor exposes a polished collapsible/expandable day-context panel bound
  to the selected date: calendar events/all-day items, reminders, tasks,
  due/overdue work, schedule/time blocks, meetings, backlinks/linked documents,
  and inline voice notes. Collapse changes presentation only; it never drops
  data or stops required state reconciliation.

### Tasks, reminders, and calendar integration

- Define one vault-owned task identity/record projection shared by Epdoc task
  blocks, Palette quick capture, Today, Organize, links, search, and graph.
  Avoid a task truth in document JSON plus a conflicting app-private database.
  If a derived index is needed, it is rebuildable and vault-bound.
- A task can link bidirectionally to multiple documents/blocks, a daily Epdoc,
  a date/time block, an external calendar event/reminder, and a Canonical Graph
  record. Completion, schedule, deadline, reminder, recurrence, move, unlink,
  delete, and reopen behavior must be explicit and conflict-safe.
- Use a single long-lived EventKit owner only after explicit Calendar and/or
  Reminders permission. Request the least access that implements the chosen
  feature, include correct sandbox entitlement/usage copy, observe external
  store changes, refetch stale identities, bound/cancel range fetches, and keep
  denial/revocation/unavailable/empty states distinct.
- Apple Calendar/Reminders remains external canonical truth for its own items.
  Store stable references and user-authored link metadata, not silent duplicate
  event/reminder copies. Every create/edit/complete/delete is explicit; never
  mutate an external item merely because a daily note or task changed.
- Today may show a local read-through projection similar in product principle
  to Things, while daily/periodic Epdocs and their content remain vault-owned.
  No account, cloud API, provider, AppleScript, helper process, server, or
  hidden sync engine is introduced.

### Voice-note media contract

- Voice notes are ordinary user-authored document media, not chat/agent
  attachments. Use the smallest native AVFAudio recording/playback path that
  proves pause/resume, cancellation, interruption/error handling, metering,
  bounded duration/bytes, atomic package publication, cleanup of abandoned
  scratch recordings, and accessible inline controls.
- Do not keep a recorder, waveform animation, or audio decode loop alive when
  hidden/occluded. Waveform generation is incremental/cached and bounded;
  playback/recording never blocks the editor main thread.
- No cloud speech, provider, general model, hidden download, or background
  transcription. Optional on-device transcription needs a separate explicit
  Free-boundary, privacy, availability, asset, performance, and artifact proof;
  recording/playback must remain useful without it.

### Performance and proof

- Fetch only bounded visible date ranges; cache by permission/store-change
  generation; debounce navigation; cancel stale day/task/link requests; and
  never scan all reminders/events or all documents on each Palette keystroke.
- Add fail-first fixtures for duplicate daily-note prevention, DST/time-zone
  boundaries, permission denial/revocation, EventKit change notification,
  deleted/moved external items, recurring reminders, task/document/date link
  integrity, rapid navigation/cancellation, voice denial/interruption/failure,
  save/reopen, offline behavior, and derived-index rebuild.
- Mounted evidence must compare the six Palette sections, daily Epdoc panel,
  native popovers, task interactions, and inline voice notes with the owner
  screenshots across compact/expanded widths, light/dark, keyboard, VoiceOver,
  Reduce Motion, reduced transparency, and denied permissions. “Looks like a
  basic to-do list” is a release failure even when the data tests pass.
