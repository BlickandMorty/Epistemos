Epistemos · Architecture Note · v2026.05.23

A typed coordinate substrate for local AI — built so pixels, vectors, notes, and proofs are projections of one address space.

Epistemos is a macOS-native cognition system. The thesis is not “everything is an EML tree.” The thesis is that every data class — pixels, embeddings, notes, graph nodes, KV pages, tool results, claims, proofs — should carry a stable UAS address, a plane placement, a residency tier, an error budget if approximate, and a witness status if product-facing. Same fabric. Different projections.

01

The thesis — one substrate, many projections

The mistake a smart system can make is treating its layers as separate worlds: pixels live in shaders, vectors live in HNSW, notes live in SQLite, claims live in a ledger, proofs live in Lean files. They look different but they are the same fabric. The fabric has coordinates; the layers are coordinate systems.

Everything is one substrate object, expressed through different coordinates, planes, residencies, and primitive representations. EML is one primitive among many; the substrate fabric is wider.

Epistemos formalises this with a five-field invariant. Every data class in the system must carry the five fields below — or have an explicit waiver naming why it is exempt. Without this invariant, the system silently fractures back into separate worlds. With it, the system stays one object.

01

UAS address

Stable identity independent of residency. UasAddress { kind, payload_id }. A pixel buffer and a graph node both addressable in the same shape.

02

Plane placement

One of five: State · Episodic · Assembly · Controller · Verification. The plane tells you what the object is for, not what it’s made of.

03

Residency tier

Current-App / Verified-Floor / Capability-Ceiling. Where the object actually lives today vs where the doctrine targets.

04

Lattice / WBO budget

If the representation is compressed or approximate, the object pays into a wireless-budget-of-objective ledger. Error is accounted, not hidden.

05

WRV status

Wired · Reachable · Visible · Verified. Honest status for product-facing surfaces. The Settings chip strip surfaces this directly.

02

The nine-layer spine — what the substrate looks like from the user out

From the kernel up to the user, the system has nine named layers. Each one consumes coordinates from the layer below and produces typed projections for the layer above. The user only ever sees the top layer, but the top layer can only be honest if the eight below it carry the five-field invariant.

03

Seven laws — the substrate has to obey these or it is not the substrate

Every research branch in the corpus passes through these seven laws. A branch that violates one is preserved as Vault-tier speculation, not promoted. A branch that satisfies all seven becomes substrate.

Law 1
Density
Morph/EML approximates compact controller policies where the formal domain permits.
Law 2
Address
Every cognitive object has a stable UAS address independent of residency.
Law 3
Active-support
Only the relevant slice of notes / graph / memory / model / tools / agent wakes.
Law 4
Lattice-error
Every compressed or approximate representation pays into WBO.
Law 5
Glue
Local context must cohere before it becomes global context.
Law 6
Duplex
Hard compact and soft page-backed branches both allowed, but routing error is accounted.
Law 7
Witness
Every meaningful action is typed, permissioned, logged, replayable, and visible.

08

Honest boundaries — what this architecture does and does not claim

Does claim

  • Local-first cognition with cloud as optional escalation, never silent fallback.
  • Closed-citation retrieval: an answer may not name a source the retrieval didn't return.
  • Zero-copy address space across Swift, Rust, Metal, MLX, KV, and HNSW on the hot path.
  • Every approximation pays into a Wyner-Ziv error ledger that is visible in Settings.
  • Every meaningful action is replayable from the RunEventLog alone.

Does not (yet) claim

  • Arbitrary live neuron control. The substrate is building active-support and circuit-adjacent routing — not direct neuron steering.
  • Tier-3 research-only paths in MAS. Research-tier kernels stay in epistemos-research/ and never ship in the App Store build.
  • That MLX is the architecture. MLX is one runtime backend. The architecture is the address / retrieval / admission / witness substrate around any backend.
  • That deferred work is dropped work. Every deferred item is targeted (see §7).
